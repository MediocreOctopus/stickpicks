# stickpicks

A fan-made NHL 2026–27 prediction game. Players pick each team's games (W / L / OTL plus combined goals), earn up to 2 points per game, and compete on per-sheet leaderboards. Static site on GitHub Pages + Supabase (Postgres, auth) + a GitHub Action (every 15 minutes) that syncs data.

Owner is not a professional developer: explain changes in plain language, and say exactly which files changed and whether `supabase/schema.sql` must be re-run.

**Brand name:** always **stickpicks**: one word, all lowercase, even at the start of a sentence or in titles. Never "Stick Picks", "StickPicks" or "Stickpicks".

## Stack and constraints

- **No build step, no framework, no npm dependencies for the site.** Plain HTML, CSS, and vanilla JS. Pages load `supabase-js` v2 (UMD) from jsDelivr, then `config.js`, then `teams.js`. These script tags sit at the **end of `<body>`**, just before each page's inline script (so the page paints before they download); only the stylesheet and fonts load in `<head>`.
- **Hosting:** GitHub Pages, deployed by `.github/workflows/deploy-site.yml` on every push to `main` (Pages source: "GitHub Actions"). It copies the site (leaving out `supabase/`, `scripts/`, `marketing/`, `.github/`, README and this file), stamps the version into every `__V__`, and publishes. That stamp is the only "build"; the files are still plain HTML/CSS/JS that run as-is.
- **Repositories:** the site is `MediocreOctopus/stickpicks` (renamed from `nhl-picks` on 2026-10-14; the local folder is still `Documents/GitHub/nhl-picks`). A separate tiny public repo `MediocreOctopus/nhl-picks` (GitHub Pages from `main`) only holds `index.html` + `404.html` that forward old `mediocreoctopus.github.io/nhl-picks/<page>?<query>` links to `https://stickpicks.hockey/<page>?<query>`; don't delete it. The localStorage keys starting `nhl-picks-` are unrelated to the repo name and must not be renamed.
- **Database:** Supabase. All schema lives in `supabase/schema.sql`, which must stay **idempotent** (safe to re-run on an existing database): `create table if not exists`, `drop policy if exists` before `create policy`, `create or replace function`. If a function's return columns change, `drop function if exists` first.
- **Data sync:** `.github/workflows/update-games.yml` runs `scripts/update-games.mjs` every 15 minutes (Node 20, no dependencies) with repo secrets `SUPABASE_URL` and `SUPABASE_SECRET_KEY`.

## Data model (Supabase)

- **New tables need explicit grants (Supabase change, Oct 30, 2026).** Supabase no longer gives new tables in `public` Data API access automatically. Every `create table public.…` added to `schema.sql` must, in the same section, enable RLS, add its policies, and `grant` exactly the access the site needs (e.g. `grant select on public.x to anon, authenticated;` for public reads, `grant select, insert, update, delete on public.x to authenticated;` for player-owned rows guarded by RLS, and the writes `service_role` needs for the GitHub jobs). Without them, supabase-js returns "permission denied". Tables reached only through `security definer` functions need no table grant (e.g. `badge_case`, `brackets`, `chiclet_awards`). The 17 tables that existed before Oct 30, 2026 kept their old automatic grants; `schema.sql` doesn't yet list all of them, so running it on a brand-new project may miss a few. Check the live grants in the SQL editor and write them into `schema.sql` before relying on it for a rebuild (backups restored with `pg_restore` keep their grants). This matters first for league play's new tables (groups).
- `games` (PK `game_id`): season, game_type (2 regular season, 3 playoffs), ot_periods (once final: overtime periods played, 0 in regulation, 2 = double OT; from the feed's `periodDescriptor`, see `otPeriods()` in `scripts/update-games.mjs`; the schedule feed's `gameOutcome` only ever says "OT"; the playoff badges Free Hockey / More Free Hockey / Even More Free Hockey need ot_periods ≥ 1 / 2 / 3, so a 4OT game earns all three), game_date, start_utc, home, away, home_score, away_score, game_state, schedule_state (`PPD` = postponed), period_type (`REG`/`OT`/`SO`, set only when final), venue, neutral_site. Public read; only `service_role` writes.
- `team_picks` (PK user_id, team, game_id): `pick` (W/L/OTL, nullable), `goals` (0–30, nullable); at least one must be set. RLS: owner only, and only while `pick_is_open(game_id, team)` is true (before puck drop, team actually plays in that game).
- `profiles` (PK user_id): `username`, 3–20 of `[A-Za-z0-9_]`, unique case-insensitively; `avatar_kind` (null/`sweater`/`photo`), `avatar_team`, `avatar_number` (0–99), `avatar_url` (checked by `profiles_avatar_valid`: photos must be in `avatars/<user_id>/`). Public read. Query it with `select("*")` so pages don't break before a schema update.
- Storage bucket `avatars` (public read, 2 MB, webp/jpeg/png): one file per player at `<user_id>/avatar`; players can only write their own folder. The profile page crops photos square to 256 px and saves WebP (JPEG fallback) before upload; the stored URL ends `?v=<timestamp>` to bust caches.
- `news`: ESPN headlines for the ticker. Public read.
- `user_settings` (PK user_id): `look` (auto/home/road). **Private**: owner-only RLS (unlike `profiles`, which is public).
- Functions (security definer unless noted): `delete_my_account()` (deletes the caller from auth.users; cascades remove profile, picks, settings); `leaderboard(p_season, p_team, p_from, p_to)` returns one row **per user per team sheet** (optional `p_from`/`p_to` game dates make the weekly and monthly boards); `sheet_picks(p_username, p_team, p_season)` returns another player's picks with **upcoming picks hidden** (`revealed=false`, pick/goals null); `username_available(p_username)`; `my_sheets(p_season)` (security invoker); `pick_is_open(game_id, team)`.

## Game rules (enforce everywhere: JS, SQL, rules page)

- From the sheet team's side: **W** = any win (incl. OT/SO); **L** = regulation loss; **OTL** = OT or shootout loss.
- **Combined goals** = `home_score + away_score` from the official final score, which credits the shootout winner with one goal (2–2 then SO win = 3–2 = 5 goals).
- 1 point for correct result + 1 point for exact combined goals; max 2 per game. Scored only when `period_type` is set.
- Picks lock at **puck drop** (`start_utc`), enforced by RLS, not just the UI.
- Leaderboards rank each **team sheet separately**; points are never summed across sheets. Ties share a rank.
- Other players' picks are revealed only for games that have started.

## Conventions

- **Site updates and Press Box (owner's rule; full guide in `UPDATES.md`):** every push that changes something players can see or use adds a new entry to the top of `PRESS_BOX` in `pressbox.js` *in the same push*, with the next version (season year + number: 26.1, 26.2 …; the season's first is a named .0). Entries are concise, never use "you", "your" or "you're" (or "we"), and follow the writing rules in `UPDATES.md`. Every new entry also gets drafted posts for each social media account listed in `UPDATES.md` section 7 (today: Bluesky), each linking to the entry: `https://stickpicks.hockey/pressbox.html?ref=<account>#v<version>`. Behind-the-scenes-only pushes (workflows, notes, backups) get no entry.
- Picks in the browser: `{ [game_id]: { o: "W"|"L"|"OTL", g: number } }`. Older saved data may be a bare string; `loadLocal()` normalizes it.
- localStorage keys (don't rename; users have data in them): `nhl-picks-${SEASON}-${team}`, `nhl-picks-last-team`, `stickpicks-breakaway-hi`. Also `stickpicks-look` (auto/home/road), `stickpicks-me` ({name, avatar} of who's signed in on this device), `stickpicks-recap-${userId}` ({base, last}: the start of the previous visit and the current one, for the home "Since your last visit" recap; a new visit starts after 3+ hours away), `nhl-picks-games-${SEASON}-${team}` (last schedule, so a sheet opens offline) and `stickpicks-install-dismissed` (hides the install bar for 30 days) and `stickpicks-pressbox-seen` (newest Press Box version this device has opened).
- App behaviour (`teams.js`): `mountInstall()` fills `#installBar` on the home page with an Install button (from the browser's `beforeinstallprompt`) or, on iPhone/iPad, Add to Home Screen steps; it never shows inside the installed app. `mountOffline()` adds a notice while offline.
- Constants declared with `const` in `teams.js` are script-level globals, **not** `window` properties. Check them with `typeof TEAMS !== "undefined"`, not `window.TEAMS`.
- Supabase auth: email + password, sessions persist. Don't `await` Supabase calls inside `onAuthStateChange`; defer with `setTimeout(…, 0)`.
- Build DOM with `textContent` for any user-supplied text (usernames). Don't interpolate it into `innerHTML`.
- Brand ("Barnstormer", old-school hockey sweater): cream wool knit (`--wool #EFE6D2`), navy (`--navy #1C2B45`), cardinal red (`--red #9B1C1F`, brighter `#E8463F` in dark mode), gold accent. Light mode is the cream **home sweater**; dark mode is the navy **road sweater** (`.home` pages swap `--bg/--panel/--ink/--btn…`). Recurring motifs: knit texture on `body`, `.hem`/`.hem-top` stripe bands, team-colour sleeve stripes on game cards (`--away-*`/`--home-*` set in `index.html`) and on sheet headers (`.board::after`).
- Team colours: `board` is each team's **primary** colour from its official palette, even when it's light (Nashville gold, Philadelphia/Anaheim orange). Never hard-code white text on a team colour: use `var(--board-ink)` on headers and `var(--t-ink)` on chips/tiles.
- Look / dark mode: a tiny inline `<script>` in every page's `<head>` (before styles.css) sets `html[data-scheme="dark"|"light"]` from `stickpicks-look` (Auto follows the device). Dark styles are written as `[data-scheme="dark"] …` / `:root[data-scheme="dark"]`, **never** `@media (prefers-color-scheme: dark)`. New pages must include that head script.
- Phones and the app (≤560px): the top bar shows only the logo and Rules; the account button (`.navaccount`) is hidden because the Me tab opens the Locker Room (`locker.html`, or sign-in), with your profile one tap from there.
- Visitor stats: every page ends with the GoatCounter snippet (`stickpicks.goatcounter.com`; a `window.goatcounter.path` function counts `pathname` plus `?team=` only, never `user=`). New pages must include it. `sw.js` lets GoatCounter requests go straight to the network.
- Puck-drop reminders (web push): `push_subscriptions` + `push_reminders_sent` (no player access; functions `save_push_subscription`, `remove_push_subscription`, `has_push_subscription` for the signed-in player; `push_reminders_due(p_minutes)` for the service role only). `scripts/send-reminders.mjs` runs as a second workflow step (installs `web-push`; needs the `VAPID_PRIVATE_KEY` secret, public key in `config.js` and the workflow env). Client helpers in `teams.js`: `pushSupport()`, `remindersOn()`, `enableReminders()`, `disableReminders()`; `sw.js` handles `push` and `notificationclick` (opens `index.html#upnext`). Signing out or deleting the account removes the device first.
- Badges: `BADGES` (id, name, ring navy/red/gold, how, inline SVG art) and `badgeEl()`, `computeBadges()`, `myBadges()`, `playerBadges()`, `announceBadges()`, `badgesInReach()`, `badgeProgressEl()` in `teams.js`; `computeBadges()` returns `meter[id] = [have, need, what]` for progress bars. The "faceoff" id is now the Rookie badge (id kept so it isn't re-announced). Shown from the browser's own calculation, but **Chiclets rewards are paid only from the database's check** (`badges_earned()` in `schema.sql`, section 18), so **any badge rule change must be made in both `computeBadges()` and `badges_earned()`**. localStorage `stickpicks-badges-${userId}` = badges already announced on this device.
- Chiclets (free points, never sold, no cash value): `chiclets_ledger_uid()` works out every change from picks, final scores, badge rewards (`chiclet_awards`) and shop purchases (`chiclet_spends`); `chiclets_ledger()` (your own statement only) and `chiclets_balance()` (anyone's total) wrap it. Rules: +1 right result, +2 exact goals, each game pays once per player (only what every pick on it got right), +5 perfect night, badge rewards navy 5 / red 10 / gold 25 / rivalry 5, −1 per missed game on a started sheet (max −5 a week), never below 0. The counter (`chicletChip()`, `mountChicletNav()`) sits top right on most pages. Prices: Starter 150, Classic 400, Premium 800, Legendary 1500.

- The sweater: `jerseyMarkup(style, {j1,j2,j3})` in `teams.js` is the one drawing used for every sweater (hockey sweater laid flat: long angled sleeves, V-neck). Sleeve stripes are drawn in each sleeve's own frame (`SLEEVE_FRAME`) so they wrap the arm; `sweaterColours(team, style)` gives the colours.
- Profile Settings are closed until the Settings button in the banner opens them (`openSettings()`); `profile.html#settings` and `#reminders` open them.

## Known gotchas

- The NHL feed (`api-web.nhle.com`) is undocumented and can change. Browsers can't call it directly (CORS), which is why the GitHub Action exists.
- New tables need explicit grants. `service_role` needs `select, insert, update` (and `delete` where the job deletes) or the Action fails with `42501 permission denied`.
- PostgREST returns at most 1000 rows by default. Use aggregate functions instead of pulling raw picks.
- Supabase's built-in email sender allows only a few emails per hour (confirmations + password resets).
- GitHub pauses scheduled workflows after 60 days without repository activity. `keepalive.yml` re-enables all of them (update-games, keepalive, monitor, backup, weekly-report, reminders; add new scheduled workflows to its list) on the 1st of each month; if GitHub emails that a workflow was disabled, re-enable it in the Actions tab.

## Testing

There's no automated test suite. When changing pages, check them in a browser with real or stubbed Supabase data, including a phone-width viewport (~390px) and dark mode. Verify scoring changes against the examples table in `rules.html`. After editing `supabase/schema.sql`, re-read it for idempotency before telling the owner to run it in Supabase's SQL Editor.

Sign-in trouble: Supabase's dashboard (**Logs → Auth**, or Logs Explorer on `edge_logs`, whose request headers carry the user agent and `x_client_info` = the supabase-js version) shows which device and library version is calling `/token`. A storm of `refresh_token` 400/429s from one device means a stale page is looping; it rate-limits that device's network, and Safari reports the blocked sign-in as "Load failed".

## Backups: restoring
Download the backup from Actions → "Back up the database" → a run → Artifacts (a zip holding `stickpicks-backup-YYYY-MM-DD.tgz.gpg`).
1. Decrypt and unpack: `gpg --decrypt stickpicks-backup-DATE.tgz.gpg > backup.tgz` (asks for BACKUP_PASSPHRASE), then `tar -xzf backup.tgz`.
2. Inside: `public.dump` (site tables, functions, policies, data), `auth.dump` (sign-in accounts, data only), `row-counts.txt`.
3. Restore into a Supabase project (PostgreSQL 17 tools; use the Session pooler connection string as `$DB`):
   accounts first, `pg_restore --data-only --disable-triggers -d "$DB" auth.dump`, then the site,
   `pg_restore --clean --if-exists --no-owner -d "$DB" public.dump`. Compare table sizes with `row-counts.txt`.
   To restore one table only: `pg_restore --data-only -t team_picks -d "$DB" public.dump` (empty it first).
Restoring over the live project replaces current data: try it on a spare Supabase project first.
